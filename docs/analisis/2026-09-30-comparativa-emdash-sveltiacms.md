## Tabla comparativa de funcionalidades: EmDash vs Sveltia CMS (2026)

| Categoría | Funcionalidad | EmDash (2026) | Sveltia CMS (2026) |
|---|---|---|---|
| **Modelo y arquitectura** | Tipo de CMS | Full‑stack, serverless; backend propio con admin, API y base de datos.  [blog.cloudflare](https://blog.cloudflare.com/emdash-wordpress/) | Headless Git‑based; sin backend propio, el contenido son archivos en tu repo.  |
| | Stack principal | TypeScript + Astro 6; corre en Cloudflare Workers (y también en Node/SQLite).  [blog.cloudflare](https://blog.cloudflare.com/emdash-wordpress/) | Svelte; SPA servida desde CDN; framework‑agnóstica para el sitio.  |
| | Almacenamiento de contenido | D1 (SQLite distribuido) u otras DB SQL (Turso/Postgres) + R2/S3 para medios.  [blog.cloudflare](https://blog.cloudflare.com/emdash-wordpress/) | Archivos en Git (Markdown/YAML/JSON); sin DB externa.  |
| | Filosofía | “Sucesor espiritual de WordPress” moderno y seguro.  [blog.cloudflare](https://blog.cloudflare.com/emdash-wordpress/) | Sucesor moderno de Netlify/Decap CMS, centrado en Jamstack.  |
| **Admin y edición** | Panel de administración | Admin completo: esquema visual, menús, taxonomías, widgets, importador de WordPress.  [npmjs](https://www.npmjs.com/package/@sveltia/cms?activeTab=readme) | Admin ligero pero moderno: lista de entradas, editor por colección, vista previa.  [sveltiacms](https://sveltiacms.app/en/docs/intro) |
| | Editor de contenido | Campos tipados; soporte para bloques estructurados (Portable Text).  [npmjs](https://www.npmjs.com/package/@sveltia/cms?activeTab=readme) | Campos configurables (string, markdown, relation, etc.) y widgets.  |
| | Vista previa (preview) | Previsualización de contenido antes de publicar (integrado con el sitio).  [github](https://github.com/emdash-cms/emdash/blob/main/README.md) | Preview pane que muestra todos los campos y su estado de llenado.  [till-freitag](https://till-freitag.com/en/blog/cloudflare-infrastructure-play-en) |
| | Borradores y revisiones | Borradores y revisiones gestionados en la DB del CMS.  [github](https://github.com/emdash-cms/emdash/blob/main/README.md) | Flujo vía Git: ramas/PRs para revisión; depende de tu repo y CI.  |
| **Contenido y modelo de datos** | Esquemas/colecciones | Colecciones con esquema visual; campos y relaciones definidos en config.  [npmjs](https://www.npmjs.com/package/@sveltia/cms?activeTab=readme) | Colecciones y archivos configurables en YAML/JSON; campos y validaciones.  |
| | Formatos soportados | Contenido estructurado (Portable Text) + medios en R2/S3.  [npmjs](https://www.npmjs.com/package/@sveltia/cms?activeTab=readme) | Markdown, YAML, JSON, TOML, etc., según config.  |
| | Taxonomías | Soporte nativo (categorías, etiquetas, menús).  [npmjs](https://www.npmjs.com/package/@sveltia/cms?activeTab=readme) | Configurable mediante colecciones y campos (no hay “taxonomías” como en WP por defecto).  |
| | Menús/navegación | Menús de navegación gestionados desde el admin.  [npmjs](https://www.npmjs.com/package/@sveltia/cms?activeTab=readme) | No hay gestión de menús “out of the box”; se modela como contenido si se necesita.  |
| **Medios y archivos** | Biblioteca de medios | Media library con drag‑and‑drop, uploads por URLs firmadas, almacenamiento en R2/S3.  [npmjs](https://www.npmjs.com/package/@sveltia/cms?activeTab=readme) | No tiene media library propia; los medios suelen estar en el repo o en un servicio externo (p. ej., Cloudinary).  |
| | Transformaciones de imagen | Depende de integración (p. ej., Workers/edge o servicios externos); no es un procesador de imágenes en sí.  [blog.cloudflare](https://blog.cloudflare.com/emdash-wordpress/) | No incluye procesamiento; se delega al SSG/CDN o servicios de imágenes.  |
| **Internacionalización (i18n)** | Soporte multilingüe | Configurable a nivel de colecciones/campos; enfoque en contenido estructurado.  [npmjs](https://www.npmjs.com/package/@sveltia/cms?activeTab=readme) | i18n de primera clase: estructuras flexibles, config a nivel global/colección/campo.  [docs.emdashcms](https://docs.emdashcms.com/coming-from/astro/) |
| **Autenticación y roles** | Login y auth | Passkeys (WebAuthn) por defecto; OAuth y magic link; auth pluggable (SSO empresarial).  [blog.cloudflare](https://blog.cloudflare.com/emdash-wordpress/) | Sin auth propia; usa auth del proveedor Git (GitHub/GitLab/Bitbucket) y permisos del repo.  |
| | Roles y permisos | RBAC incluido: Administrator, Editor, Author, Contributor.  [cmswire](https://www.cmswire.com/digital-experience/meet-emdash-the-cloudflare-cms-and-the-wordpress-spiritual-successor/) | Permisos heredados del repo/organización Git; no hay roles internos del CMS.  |
| **Extensibilidad** | Sistema de plugins | Plugins en isolates (Dynamic Workers), con hooks, KV, settings, páginas admin, widgets, bloques y rutas API.  [blog.cloudflare](https://blog.cloudflare.com/emdash-wordpress/) | Sin marketplace de plugins; extensión vía configuración, widgets y flujos Git/CI.  |
| | API | REST API integrada para contenido y administración.  [npmjs](https://www.npmjs.com/package/@sveltia/cms?activeTab=readme) | No expone API propia; el contenido se lee directamente del repo/SSG.  |
| **Flujo de publicación** | Publicación y deploy | Publica en la DB; el sitio (Astro SSR/SSG) consume la API/DB para renderizar.  [npmjs](https://www.npmjs.com/package/@sveltia/cms?activeTab=readme) | Cada cambio es commit/PR; el deploy lo hace tu CI/CD (Vercel, Netlify, Cloudflare Pages, etc.).  |
| | Entornos y preview | Previsualización integrada; entornos según config del deploy.  [github](https://github.com/emdash-cms/emdash/blob/main/README.md) | Preview por PR/branch según config de tu pipeline.  |
| **Migración e importación** | Importadores | Importador de WordPress incluido.  [npmjs](https://www.npmjs.com/package/@sveltia/cms?activeTab=readme) | No hay importador “oficial” WP; migraciones típicas vía scripts a Markdown/YAML.  |
| **Hosting y operación** | Dónde corre | Diseñado para Cloudflare (Workers + D1 + R2), pero puede correr en Node/SQLite u otras DB.  [blog.cloudflare](https://blog.cloudflare.com/emdash-wordpress/) | La UI se sirve desde CDN; el contenido vive en tu Git; el sitio en cualquier hosting estático/SSG.  |
| | Operación y escalado | Serverless: escala a cero, se paga por uso en Workers; sin servidor que mantener.  [blog.cloudflare](https://blog.cloudflare.com/emdash-wordpress/) | Sin servidor de CMS que operar; costos ligados a Git + hosting estático/SSG.  |
| | Vendor lock‑in | Fuerte orientación a stack Cloudflare (aunque hay abstracciones portables).  [blog.cloudflare](https://blog.cloudflare.com/emdash-wordpress/) | Mínimo: Git + CDN; portable entre proveedores.  |
| **Madurez y ecosistema** | Estado en 2026 | Beta pública desde abril 2026; open source (MIT); ecosistema de plugins en crecimiento.  [blog.cloudflare](https://blog.cloudflare.com/emdash-wordpress/) | Beta activa con roadmap 2026; ya usado en producción; sucesor de facto de Netlify/Decap.  |
| | Casos típicos | Agencias y proyectos que buscan “WordPress moderno” serverless con plugins seguros.  [blog.cloudflare](https://blog.cloudflare.com/emdash-wordpress/) | Sitios Jamstack/SSG que quieren contenido en Git con UX moderna y i18n robusto.  |
